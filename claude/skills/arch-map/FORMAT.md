# 架构地图的格式

arch-map（从代码画）和 arch-design（先设计后写代码）共用这一份。改格式只改这里。

## 结构

全部放在 `<git 根>/docs/arch/`，文件名前缀决定 mmd-view 侧栏的顺序：

| 文件 | 内容 | 节点上限 |
|---|---|---|
| `00-overview.mmd` | 总览：用户、外部服务、存储，加上本项目的几个大块 | 10 |
| `10-modules.mmd` | 模块地图：项目内部的模块和依赖方向（为了连线可以放存储节点） | 15 |
| `2N-flow-<名>.mmd` | 关键流程，3–5 条：一个请求 / 任务从入口走到落地 | 15 |
| `3N-<模块>.mmd` | 模块细节：只给复杂到需要放大的模块 | 15 |
| `CHANGES.md` | 每次生成 / 更新一段，新的在上 | — |
| `DESIGN.md` | 只有 arch-design 用：决策、待定问题、实现顺序 | — |

超过上限就拆：把一团节点收成一个节点，细节放进下一层，用 `@link` 连过去。
图已满又要加节点，就合并那些在下一层还有细节的节点（标签写「×N」）。

**链接**：一个节点最多一条 `@link`（双击只能进一张图）。总览里代表本项目主体的节点 `@link` 到
`10-modules.mmd`；模块 `@link` 到它的细节图或它最主要参与的流程。每张图都要能从总览沿 `@link` 走到。

**流程怎么选**：先选运行中的产品为用户做的事、核心的后台循环；开发工具、构建脚本只在名额有剩时才画。

## 写法

- 只用 `flowchart`（LR 或 TD）。高亮上下游、跳源码、手绘线条都只对流程图生效。
  只有「来回多次的交互顺序」本身就是重点时，才用 `sequenceDiagram`。
- 不写 frontmatter、`%%{init}%%`、颜色，风格由 mmd / mmd-view 统一给。例外只有下面的 `changed` / `planned`。
- 节点 id 用短的 ASCII snake_case；标签写「中文说明<br/>代码里的名字」，如 `order_svc[订单服务<br/>OrderService]`。
  标签里有 `( ) [ ] { } : ; |` 或以 `/` 开头时，整个标签加双引号：`api["接口<br/>GET /api/sessions"]`。
  标签里不要出现 `#` 和双引号。
- 边 = 调用、导入、读写、发消息。边标签写动词或协议（`HTTP`、`写入`、`订阅`）；异步用虚线 `-.->`。

## 注释行（集中放在文件末尾）

| 写法 | 作用 |
|---|---|
| `%% @src <id> <相对 git 根的路径> <锚点>` | 节点的**证据**：双击跳到源码 |
| `%% @link <id> <另一个.mmd>` | 双击进入细节图（路径相对当前 .mmd） |
| `%% @note <id 或 *> <一行>` | **用户的备注**（`*` = 整张图），用户在 mmd-view 里按 `n` 写 |
| `%% @commit <hash>` | 只在 `00-overview.mmd`：这份地图对应的提交；设计阶段还没有代码时写 `none` |

末尾顺序：注释行一块，`classDef`（如有）放最后。

**锚点**是定义那一行里的一段文字（`def create_order`、`class Board`），在文件里必须唯一；
打开时现场找行号，代码上下挪动不会指错。**不写行号**——一加 import 全部错位。锚点指向：

- 类 / 函数 / 路由注册 → 定义行；
- 节点代表整个文件 → 它的入口（`main`、`if __name__`、systemd 的 `ExecStart`、HTML 主脚本的初始化函数）；
- 几份相似文件合成一个节点 → 标签写「×N」，指其中一份代表，并在汇报里说明；
- 不唯一就加长，直到 check.py 不报。

外部系统、存储不标 `@src`：用户、第三方服务、外部命令、数据库实例、运行时读写的数据文件 / 目录、静态素材。

**边的证据**：每条边都要找到对应的那一行代码，记在你的笔记里，找不到就不画。
两种边可以没有单行代码对应：外部动作（用户打开页面），以及简化边——跳过了中间层，
或者由大块里没单独画出来的文件发起——后者在边标签里写「经 X」。拿不准的写进汇报，不画进图。

**备注是用户的**：不改写；唯一能删的时机是 arch-design 把它转成了 `DESIGN.md` 里的决策、且用户在对话里确认过。节点改名就把备注的 id 跟着改；节点删了就改成
`%% @note * （原 <id>）<原文>`。check.py 会拦下挂在不存在的节点上的备注。

## 两种标记

| 标记 | 含义 | 文件末尾要有 |
|---|---|---|
| `:::changed` | 这次更新里**代码**新增或变了的节点（只为腾名额合并的不标；只多 / 少一条边时标它的起点） | `classDef changed stroke:#e0af68,stroke-width:3px,stroke-dasharray:7 4` |
| `:::planned` | 设计好了、**代码还没写**的节点，不需要 `@src` | `classDef planned stroke:#bb9af7,stroke-width:2px,stroke-dasharray:3 4` |

计划中的节点代码落地后：去掉 `:::planned`，补上 `@src`。

**`@commit` 和「脏」**：`@commit` 记画图时的 `git rev-parse --short HEAD`。`docs/arch/` **以外**还有未提交改动
（`git status --porcelain -- . ':(exclude)docs/arch'` 不为空）时加后缀 `+dirty`；`docs/arch/` 自己没提交不算脏。

## 校验

`python3 ~/.claude/skills/arch-map/scripts/check.py <项目根>/docs/arch`，退出码 0 才算完成。
`✗` 是错误；`·` 开头的是要逐个过一遍的提示（没标 `@src` 的节点必须是外部系统、存储或 `planned`）。

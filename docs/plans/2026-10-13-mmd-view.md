# 设计：mmd-view 第二轮优化

## 目标

mmd-view 是私人定制的看图工具（`bin/mmd-view` + `share/mmd-view/viewer.html`）。2026-10-13 实测性能已经够用：
扫文件 < 2 ms、首开 363 ms、重画 74 ms、平移每帧 0.03 ms，所以**这一轮不碰性能**，只做四件事：
堵住「别的网页能遥控它」、同一目录不重复开窗口、从细节图返回时恢复状态、导出 PNG。

## 决策

### 1. 防遥控（安全）

**问题（已实测）**：伪造 `Host: evil.example` 请求 `/api/files` 返回 200；跨站 `text/plain` POST 到 `/api/note`
不触发预检，服务照常解析（只因文件名不对才 400）。也就是你在普通浏览器里打开的任何网页，扫到端口后都能往 `.mmd`
写 `%% @note`，而 `/arch-design` 会把备注当需求处理，这就成了往 AI 指令里注入内容的通道；也能用 `<img>` 不停触发
`/api/open` 让 nvim 乱跳。

- **所有请求都校验 Host**：只认 `localhost:<端口>` 和 `127.0.0.1:<端口>`，其他一律 403。这样就挡住了 DNS rebinding。
- **`/api/*` 必须带请求头 `X-MMD-View: 1`**，没带就 403。跨站请求带自定义头会先发预检，服务不响应 CORS，浏览器就拦下了。
  页面里的 fetch 统一走一个 `api()` 小函数，自动带上这个头。
- **`/api/events` 例外**：浏览器的 EventSource 加不了自定义头。它只读、没有副作用，跨站读也被 CORS 挡住，有 Host 校验就够了。
- 不引入 token / cookie：自定义头 + Host 校验已经堵住上面实测出的两条路，用不着更重的方案。

### 2. 单实例：已经开着的窗口优先复用（用户定：包含这个文件的窗口都复用）

- **登记处**：`$XDG_RUNTIME_DIR/mmd-view/<端口>.json`，内容是 `{root, port, pid, win}`。这个目录在 tmpfs 上，重启自动清空。
  服务退出时删掉自己的登记；进程已经死了的残留登记，在查找时顺手清掉。
- **双击文件时**：找 `root` 包含这个文件、而且文件在它侧栏列表里的实例，有多个就选目录最深的。
  向它发 `POST /api/goto {f}`，它通过 SSE 让页面跳过去（改 `location.hash`，`Alt+←` 照样能回来），
  启动的这一方再用 `hyprctl` 按窗口地址把窗口切到前台，然后退出。
- **打开目录时**：只复用同一个目录的实例。打开上层目录的实例的话，侧栏范围会对不上（默认）。
- **实例的窗口已经关了**（服务还在 8 秒的退出缓冲期里）：`/api/goto` 回 409，启动方改为新开一个窗口。
- **窗口地址怎么拿**：启动 Chrome 前后各取一次 `hyprctl clients -j`，在 5 秒内找 class 为 `chrome-localhost__-Default`
  的新窗口，地址写进登记。**不靠窗口标题**，因为不同项目的图都叫 `00-overview.mmd`，按标题会认错。
  找不到地址时照样跳图，只是不切前台。
- `--no-browser`（调试用）不参与登记和复用。

### 3. 从细节图返回时恢复状态（用户定：缩放位置 + 选中的节点）

- 页面在内存里按「文件 + 横/竖」记 `{view, sel, deep}`，离开一张图时存下来；回到这张图时恢复视野。
  如果节点还在，就重新选中、高亮、弹出信息卡。
- 方向不同就用不同的记录：横竖切换后，旧的视野坐标没有意义。
- 任何回到一张图的方式都生效（`Alt+←`、侧栏、`@link`、单实例的 goto）。页面重新加载就清空，不写 localStorage。

### 4. 导出 PNG（用户定：剪贴板 + 存文件；所见即所得）

- 按 **`e`**，顶栏加一个「导出」按钮。**只出 PNG**：SVG 不嵌字体，发给别人会变样（docs/05 坑 3）。
- **在浏览器里完成**（已实测可行）：克隆当前 SVG，画到 canvas 上再 `toBlob`。foreignObject 不会污染画布，
  手写体和小赖字体都保留了（`00-overview` 导出 3923×1068，没问题）。不用绕回 `mmd`，也就不用再起一个 Chrome。
- **所见即所得**：范围 = 当前窗口里看得到的区域（按舞台四角换算成 SVG 坐标，不是 `view`，
  因为 `preserveAspectRatio` 会在一个方向上多露出一截），保留选中高亮、变暗效果、搜索命中和备注黄点。
  **信息卡、顶栏、侧栏不导出**，它们是界面，不是图。
- 高亮样式现在写在页面 CSS 里（`.dim` / `.hl-*` / `.e-*` / `.note-dot`），而且用了 `var(--yellow)` 这类变量，
  SVG 单独当图片渲染时这些都没有。所以把这一段 CSS 单独放进 `<style id="hl-css">`；
  导出时取它的文本，把 `var(--x)` 换成实际颜色值，再塞进克隆出来的 SVG。页面和导出共用同一份样式。
- 分辨率是舞台像素的 2 倍（同 `mmd -s 2`），背景色 `#1a1b26`。超出 Chrome 画布上限（单边 16384、总面积约 2.68 亿像素）就自动降低倍数。
- **复制到剪贴板**：`navigator.clipboard.write(ClipboardItem image/png)`。localhost 算安全上下文，按键本身就是用户操作，满足调用条件。
- **存文件**：`POST /api/export`，服务写到 `~/Pictures/mmd_<图名>_<YYYYmmdd_HHMMSS>.png`，和截图放在一起，命名风格也一致。
  文件名由服务端生成、只用安全字符，请求体上限 50 MB。
- 完成后弹提示「已复制 + 存到 ~/Pictures/…」；剪贴板失败但文件存成功时，如实说明哪一步失败了。

## 实现顺序

- [x] 1. **防遥控**：服务加 Host 校验和请求头校验；页面加 `api()` 小函数，替换所有 fetch。
  验证：伪造 Host → 403；不带请求头 → 403；跨站 text/plain POST → 403；真实页面各项功能正常（puppeteer 跑一遍）。
- [x] 2. **返回恢复**：页面加按「文件 + 横/竖」记录的状态表。
  验证：puppeteer 里选中节点、缩放、切到另一张图再 `history.back()`，视野和选中都还原；切横竖后不套用旧视野。
- [x] 3. **导出**：抽出 `hl-css`、实现 `exportPng()`、加 `/api/export`、按钮和 `e` 键。
  验证：puppeteer 导出带高亮的局部视野，看图确认高亮和字体都在；文件落进 `~/Pictures`；超大图会降倍数。
  剪贴板在无头模式下测不了，留到第 5 步在真窗口里测。
- [x] 4. **单实例**：登记、查找、`/api/goto`、SSE goto 消息、抓窗口地址、切前台、清理残留登记。

  关掉窗口后 8 秒内再开，会新开一个；开一个不相干的目录，会新开一个。
- [x] 5. **真窗口验收**：剪贴板粘贴、导出、单实例切前台，在真实的 Hyprland 下各走一遍。

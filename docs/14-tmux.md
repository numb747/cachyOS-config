## 0 · 本机现状

- **tmux 3.8**（2026-10-10 随 `pacman -Syu` 升上来的）。
- 终端链是 **kitty → nvim `:terminal` → zsh → tmux**（kitty 的 `shell` 直接起 nvim，见
  [03](03-terminal.md#kitty--打开终端直接进-nvim)）。所以 tmux 的「外层终端」其实是 nvim，
  `tmux list-clients -F '#{client_termtype}'` 报的是 `libvterm(0.3)` —— 那就是 nvim 的终端库。
- **前缀是 `C-q`**（2026-10-11 从 `C-b` 改的，只当备用；`C-b` 还给了 Claude Code 的「命令转后台」）。
  平时用第 1 节的 Alt 键。下文 `前缀 x` 都指「先按 `C-q` 松开，再按 `x`」。

### 「复制不出来」是怎么回事（2026-10-11）

升到 3.8 之后在 tmux 里选多行，按 `v` 开始选、按 `y` 复制，什么都没进剪贴板。两个原因叠在一起：

1. **没有配置文件，tmux 自己猜成了 vi 键位** —— 它看 `$EDITOR`/`$VISUAL` 里有没有 `vi`，
   本机 `EDITOR=vim`，于是 `mode-keys vi`。
2. **vi 键位的默认绑定和 vim 习惯不一样**：`v` 是**切换块选择**（不是开始选择），
   **`y` 根本没绑定**。开始选择是 `空格`，复制是 `Enter`。

剪贴板那条路本身是通的：`set-clipboard external`（默认）发 OSC52 → nvim 的终端转给 kitty →
Wayland 剪贴板，`tmux load-buffer -w` 实测能进 `wl-paste`。现在的配置额外加了
`copy-command 'wl-copy'`，复制时**同时**用 wl-copy 直接写，不依赖 nvim 那一层转发。

## 1 · 键位：免前缀 Alt 层（2026-10-11，学 Zellij）

### 三层结构和对应的键

| 层 | 类比 | 新建 | 切换 | 关 | 改名 |
|---|---|---|---|---|---|
| **session**（会话） | 一个工作区，脱离终端也活着 | `Alt+Shift+O` 选项目目录开一个 | `Alt+o` 列表（= 原 `前缀 s`）· `Alt+j/k` 到上/下边界时穿越 · **`Alt+a` 按窗格找（第 9 节）** | 关光它的标签 | `Alt+Shift+R` |
| **window**（标签） | 浏览器的 tab，底栏一格一个 | `Alt+Shift+N` | `Alt+1~8` 直达 · `Alt+h/l` 到左/右边界时穿越 | `Alt+q`（多窗格时确认） | `Alt+r` |
| **pane**（窗格） | tab 里切出来的分屏 | `Alt+\` 左右 · `Alt+-` 上下 · `Alt+n` 自动 | `Alt+h/j/k/l` | 里面 `exit` | — |

其余：`Alt+m` 放大/还原窗格 · `Alt+f` 浮动/放回 · `Alt+v` 复制模式 · `Alt+;` 命令行 ·
`Alt+d` 脱离 · `Alt+0` 锁定 · **`Alt+a` 窗格总览（第 9 节）** · **`Alt+/` 速查菜单（忘了就按它，选中即执行）**。

- **穿越**是从 Zellij 学的：窗格和标签、会话用同一组方向键，不用分开记。
  `Alt+h` 在最左边的窗格上再按 = 上一个标签；`Alt+j` 在最下边 = 下一个会话。
- `Alt+n` 按窗格形状自动选方向：宽 > 高×2 就左右分，否则上下分（字符约 1:2）。
- 改名的输入框**是空的**，旧名字显示在提示里；直接回车 / Esc 不改。
- `Alt+q` 关掉会话里最后一个标签时切到别的会话，不会整个脱离（`detach-on-destroy off`）。
- `Alt+Shift+O`：zoxide 记录的常去目录 → fzf 选 → 有同名会话就切过去，没有就以该目录新建。
- `Alt+0` **锁定**：Alt 层和前缀全部放给里面的程序，底栏变红显示 LOCK，再按一次解锁。
  用在两处：ssh 进去的远端也开着 tmux（外层锁住，Alt 键就到了里层）；偶尔要用被占掉的程序键
  （比如 Claude Code 的 `Alt+j` 终端面板）。

### 为什么是这些键：本机的冲突表

键要穿过 **Hyprland → fcitx5 → kitty → 外层 nvim → tmux → zsh / Claude Code / nvim** 好几层，
挑的是上面几层不截、下面几层「用户确认用不到」的组合。2026-10-11 逐层核对：

| 谁 | 占了什么 | 结果 |
|---|---|---|
| **Hyprland** | `Alt+` `9 [ ] T S W E G Z Tab Space Enter` 及 `Alt+Shift+[ ] T S G Enter`；`Ctrl+1~4`；`Ctrl+Alt+HJKL`（加 Shift） | 这些按了根本到不了终端。网上常见的 `Alt+[ ]` 切标签、`Ctrl+Alt` 方向键切窗格在本机都不能用 |
| Hyprland（已让出） | 原 `Alt+\` / `Ctrl+Alt+\` / `Alt+Shift+\`（分屏终端） | 2026-10-11 从 `mykeys.lua` 第 5 节删掉，`Alt+\` 给了 tmux（见 [02](02-hyprland.md)） |
| **fcitx5** | `Ctrl+Space` 切输入法、`Super+Space`、单按左 Shift、`Ctrl+Alt+P` | 所以前缀**不能**用社区流行的 `C-Space` |
| **外层 nvim**（kitty 起的那层） | 连按两下 `Esc`、`Ctrl+/`；**转发 `Alt+Shift+标点` 时丢掉 Shift** | 见下面坑 1 |
| zsh（emacs 模式 + fzf） | `Alt+c` fzf 跳目录、`Alt+.` 上条末参数、`Alt+b/f/d` 按词、`Alt+n/p` 历史搜索、`Alt+h` run-help、`Alt+l` ls、`Alt+m`、`Alt+q`、`Alt+数字`、`Alt+a` accept-and-hold（2026-10-13 给了窗格总览） | 被 Alt 层盖掉的这几个用户都确认不用（有 zoxide 就不需要 `Alt+c`）。**不去 `.zshrc` 里删**：tmux 在外层，绑了里面就收不到，效果一样，还少维护一处 |
| Claude Code 2.1.296 | `Alt+o` fast mode、`Alt+p` 选模型、`Alt+t` 思考、`Alt+j` 终端面板；`Ctrl+B` 命令转后台、`Ctrl+G` 外部编辑器、`Ctrl+S` 暂存 | `Alt+o` 被占（用 `/fast` 代替），`Alt+j` 被占（`Alt+0` 锁定后可用）；`Alt+t` 本来就被 Hyprland 吃掉；**`Ctrl+B` 因为前缀改成 `C-q` 还回去了** |
| LazyVim | `Alt+j/k` 上下移动行 | 被占，用户不用 |

前缀候选也这么筛过：`C-b` 撞 Claude 的转后台、手指别扭；`C-a` 是 zsh/Claude 的回行首；
`C-Space` 撞 fcitx5；`C-s` 撞 Claude 暂存和 LazyVim 保存；反引号写代码时到处都是。
剩下 **`C-q`** 冲突最少（只盖掉 zsh 的 push-line）。查 Claude Code 默认键位的办法：
`strings ~/.local/share/claude/versions/<版本> | grep -oE '"(meta|alt|ctrl)\+[a-z]":"[a-zA-Z:]+"'`。

### 底栏

配色取自 noctalia 生成的 kitty 调色板（tokyonight 系，主色 `#7a88cf`），底色透明跟 kitty 毛玻璃走，
用 Nerd Font 圆角做胶囊（终端要开真彩色：`terminal-features ',xterm-256color:RGB'`，
外层 nvim 终端报的就是 `xterm-256color`）。2026-10-12 重做成**每块都是「彩色图标头 + 暗色正文」的胶囊**，
样子参考 [catppuccin/tmux](https://github.com/catppuccin/tmux) 的 rounded 和
[tmux-powerkit](https://github.com/fabioluciano/tmux-powerkit)，但**没装它们**，是照着写的：

- **左**：会话胶囊，图标头平时蓝 · 按了前缀黄 · 复制模式绿 · 锁定红色 LOCK。
- **中**：标签全是「编号 | 名字」胶囊，当前的蓝头亮色、其余灰头暗色；放大了带 󰊓，
  后台有新输出编号变黄、响铃变红。
- **右**：会话圆点（当前 ●、其余 ○，`Alt+j/k` 穿越时看得出在第几个）→ 当前目录胶囊（`~` 缩写，
  超 28 字从左截断）→ git 分支胶囊（不在仓库里不显示）→ `Alt+/` 帮助。时间刻意不放（用户不要）。
  会话圆点前面还有一段**窗格提醒计数**（Claude 等你 / 答完没看、命令跑完 / 失败没看），全 0 时不显示，见第 9 节。
- **状态栏上面空一行**（`status 2`，默认格式挪到第 1 行、第 0 行留空），和窗格内容隔开。
- 窗格顶部显示标题，当前窗格的也是胶囊：Agent Teams 时是任务名，没设标题就显示在跑的程序。

为什么不直接装现成主题（2026-10-12 查过 tmux-powerkit、janoamaral/tokyo-night-tmux、catppuccin 换
tokyonight 色、folke 官方 extras 等）：① 它们都接管 `status-left`，本机 Alt 层的 LOCK / 前缀 / 复制三态指示
就没了（powerkit 认前缀和复制，不认 `key-table off`）；② 用的是标准 tokyonight 色值，和 noctalia 按壁纸
取色的 kitty 有色差；③ 本包不用 TPM，装插件要多一个联网步骤。

⚠ 两个写外观时会踩的：

- **3.8 的三个默认样式会叠在胶囊上**：`window-status-current-style` 默认 `underscore`（当前标签多一条下划线），
  `window-status-activity-style` / `bell-style` 默认 `reverse`（有新输出的标签整块反色）。
  旧的纯文字标签看不太出来，一做成胶囊就很显眼。全设成 `default`，提醒改由编号颜色表达。
- **Nerd Font 圆角/图标（U+E000–F8FF 那段）在 AI 生成文件时会被静默吃掉**（同 nvim 的 `tabby.lua` 头部注释），
  第一版就是圆角全丢、只剩方块。改这一段时核对一下码位：
  `python3 -c "print(sorted({hex(ord(c)) for c in open('$HOME/.tmux.conf').read() if ord(c)>=0xe000}))"`，
  至少要有 `0xe0b4` / `0xe0b6`。

⚠ 换壁纸换了色系，这里的十几个色值不会跟着变（不是 noctalia 模板生成的），要手改。

### 在 nvim 终端里跑 tmux：滚走的输出进不了 buffer（2026-10-12 实测）

本机是 kitty → nvim → 终端 buffer → tmux。tmux 用**备用屏幕**（alternate screen）自己管画面和历史，
所以 nvim 终端 buffer 里**只有当前这一屏**：同样输出 300 行，直接跑 zsh 时 buffer 有 301 行，
在 tmux 里只有 22 行。「在 nvim 里随意编辑终端输出」这个好处，在 tmux 里只剩眼前一屏，
更早的历史要用 tmux 自己的复制模式（`Alt+v`）翻。关掉备用屏幕（`smcup@:rmcup@`）也救不回来：
分屏和状态栏的重绘会乱七八糟地灌进 buffer。所以分工是：**平时用 nvim 原生终端，
要分屏 / Agent Teams / 会话常驻时才开 tmux**。

同一处还有「两层状态栏」：tmux 状态栏下面紧跟着 nvim 的 lualine（`cmdheight=0`，没有命令行那一行）。
评估过让 lualine 在 tmux 终端里隐藏、把 nvim 的模式（TERMINAL / NORMAL）推给 tmux 状态栏合成一行
（`ModeChanged` → `tmux set @nvim_mode`），用户觉得没必要，**没做**。要做时注意切标签会让终端高度变一行，
Claude Code 对窗口尺寸变化敏感，要先实测。

### 写配置时踩到的坑（都是 2026-10-11 实测）

1. **外层 nvim 转发「Alt+Shift+标点」会丢掉 Shift。** 用 `nvim --headless` 开 `:terminal cat -v`
   喂按键实测：`<M-S-/>` 出来是 `^[/`，`<M-?>` 才是 `^[?`；**字母不受影响**（`<M-S-n>` → `^[N`）。
   kitty 交给 nvim 的是前一种，所以按 `Alt+?` 到 tmux 是 `Alt+/`。于是 `Alt+?`、`Alt+:`、
   `Alt+< >`、`Alt+|` 这类在本机全都**不能用**，帮助放 `Alt+/`、命令行放 `Alt+;`，
   分屏方向也不能靠 `\` 加不加 Shift 区分（才有了 `Alt+\` / `Alt+-` 这对）。
2. **参数末尾的分号是命令分隔符，引号里也是。** 菜单项写 `'命令行  Alt+;'` 会被截成 `Alt+`，
   后面所有菜单参数错位，`Alt+/` 直接报 `not enough arguments` 弹不出来。写成 `'Alt+; '`（带尾空格），
   菜单键写 `'\;'`。
3. **注释行末尾的反斜杠会续行**，把下一行配置吞进注释。注释写「……还是 Alt+\」结尾，
   下一行 `bind -n 'M-\' …` 就静默没了。注释别以 `\` 结尾。
4. **`#{e|>|f:…}` 浮点比较返回 `"0.00"`，`if -F` 把它当真**（只有空串和 `0` 是假），
   智能分屏会永远左右分。用整数比较 `#{e|>:#{pane_width},#{e|*:#{pane_height},2}}`。
5. **测试方法**：独立服务器 `tmux -L 名字 -f 配置 new -d`，`script -qfc 'tmux -L 名字 attach' out.raw &`
   造一个真客户端，`send-keys -K -c <客户端> M-h` 模拟按键再 `display -p` 看结果。
   菜单/弹窗是覆盖层，`capture-pane` 抓不到，要 grep `out.raw`。
   ⚠ `send-keys -K` 触发的 `command-prompt` 会**阻塞到提示框关闭**，脚本要把这一步放后台；
   ⚠ 同一个 socket 名 `kill-server` 后立刻 `new` 会报 `server exited unexpectedly`，换个名字。
6. 跑起来的 tmux `source` 新配置时，**删掉的绑定不会消失**（source 只加不减），要先 `unbind -n` 那几个键，
   或者干脆重启服务器。

## 3 · 复制粘贴

### 键盘（能跨屏、能翻历史）

```
前缀 [        进复制模式（或者 Alt+v）
  移动         h j k l / w b / Ctrl-u Ctrl-d / g G / 搜索 / ? n N
  v           开始选择（本配置改的；默认是 空格）
  V           整行选择
  Ctrl-v      切换块（矩形）选择（本配置改的；默认是 v）
  y           复制并退出（本配置加的；默认是 Enter，Enter 也还能用）
  q           不复制直接退出
前缀 ]        粘贴最近一次复制
前缀 =        从历史里挑一段粘贴（tmux 保存了每次复制的 buffer）
```

复制的东西同时进三个地方：tmux 自己的 buffer（`前缀 =` 能看到历史）、OSC52、`wl-copy`。
所以在 tmux 外面（浏览器、微信）直接 `Ctrl-v` 就有。

3.7 起复制模式可以显示**行号**：`:set copy-mode-line-numbers relative`，
跟 nvim 的相对行号一个意思，`10j` 这种跳法就不用数了。

### ⚠ 别在 tmux 里连按两下 Esc

kitty 起 nvim 时带了 `tnoremap <Esc><Esc> <C-\><C-n>`（[03](03-terminal.md)），
**两下 Esc 会被外层 nvim 吃掉**，切进 nvim 的普通模式，tmux 根本收不到。
复制模式里取消选择按**一下** `Esc` 就行；按多了发现「终端不动了」，按 `i` 回到 nvim 的终端模式。
同理，单独一下 `Esc` 也会被 nvim 扣留一个 `timeoutlen` 才放行（它在等第二下），有一点延迟是正常的。

## 4 · 3.6–3.8 的新东西（挑有意思的）

以下命令和键位都在本机 3.8 上用 `tmux list-commands` / `list-keys` 核对过存在；
具体行为以 `man tmux` 为准。

### 浮动窗格（3.7 引入，3.8 补全）

这是这几版最大的变化：窗格不再只能「切」，还能**浮在上面**，像 Hyprland 的浮动窗口。

| 怎么来 | |
|---|---|
| `前缀 *` | 新建一个浮动窗格 |
| `Alt+f` | 把当前窗格浮起来 / 放回去（本配置加的） |
| **Ctrl + 鼠标拖** | 拖多大就多大 |
| `前缀 >` 窗格菜单 → Float | 把现有的平铺窗格浮起来（Tile 是放回去） |
| `前缀 g` 进入 move 键表 | 然后 `1-4` 贴到四角、方向键贴到四边、`0` 铺满、`Alt+1-4` 缩成四分之一贴角 |
| Alt + 鼠标拖 | 挪位置 |

命令行版：`tmux new-pane -x 80 -y 20 'btop'`。适合临时看一眼的东西 ——
`btop`、`lazygit`、一个计算器 —— 不打乱已有的分屏布局。

**模态窗格**（`new-pane -O`）：一个窗口只能有一个，`-C` 点外面就关、`-D` 按 Esc/Ctrl-c 就关、
`-K` 把**所有**按键（包括前缀）都给它。拿来做「弹出式」工具很合适：

```tmux
# 前缀 G：弹一个 lazygit，退出即关
bind G new-pane -O -D -x 90% -y 85% -c "#{pane_current_path}" lazygit
```

（上面这行**没有**写进本包的配置，想要自己加。）

### popup（3.2 就有，3.6/3.7 修了一堆）

和浮动窗格看着像，区别是 **popup 不是窗格**：不能分屏、不能留着、关了就没了。

```bash
tmux display-popup -E -w 80% -h 80% 'htop'      # -E：命令退出时自动关
tmux display-popup -E -d '#{pane_current_path}' 'zsh'   # 临时开个 shell，用完 exit
```

### 其他

| 功能 | 怎么用 |
|---|---|
| 内置亮/暗主题 | `theme` 选项，默认 `detect`（跟终端走）；想要老配色 `set -g theme terminal` |
| 滚动条 | `set -g pane-scrollbars on`（3.8 起会自动隐藏，`pane-scrollbars-timeout` 控制） |
| 鼠标悬停即聚焦 | `set -g focus-follows-mouse on` |
| 拖已有选区调整它 | 3.8 起复制模式里直接拖选区边缘 |
| 选择进行中不会因为滚到底而退出复制模式 | 3.8 修的，以前很烦 |
| 历史行带时间戳 | `capture-pane -I`：每行进入历史的时间 |
| 进度条 | 程序发 OSC 9;4，tmux 可以转发给外层终端 |

### 事件与钩子（3.8 重写过）

3.8 把钩子建在了内部事件上，能做的事一下多了很多：

- **`wait-for` 可以等事件**：`wait-for -E` 阻塞到某个钩子/事件发生。
- **格式监视器** `set-hook -B`：每秒求值一个格式，**变了**（或配 `-T` 时**为真**）就跑钩子。
  比如「某窗格屏幕上出现了 xxx 就提醒我」不用再写 while 循环。
- **OSC 133**：shell 如果发 OSC 133 标记（命令开始/结束/提示符），tmux 会触发
  `pane-command-started` / `pane-command-finished` / `pane-shell-prompt` 钩子 ——
  「长命令跑完弹个通知」可以直接挂在这上面。⚠ 本机 zsh + p10k **默认不发** OSC 133，
  要用得先在 `.zshrc` 里开（还没做）。第 9 节的命令追踪没走这条，直接在 `preexec`/`precmd` 里
  `tmux set -p` 写窗格选项 —— 能顺带记下命令原文、退出码和耗时，OSC 133 只给「开始 / 结束」两个时刻。

老的监视选项照样好用，不依赖这些新东西：

```tmux
setw monitor-activity on     # 这个窗口有新输出 → 底栏标记
setw monitor-silence 30      # 这个窗口 30 秒没动静 → 底栏标记（「编译跑完了」）
```

## 5 · 拿 tmux 遥控 Claude Code

> 想要的是「一个大脑 claude 指挥几个小 claude」？那用 Claude Code 内置的 Agent Teams，
> 见第 7 节，不用自己拿下面这些命令搭。这一节适合「让脚本/别的程序遥控 claude」。

思路很直接：Claude Code 是个终端程序，tmux 能往任意窗格里**打字**（`send-keys`）、能**读屏幕**
（`capture-pane`）、能**等信号**（`wait-for`）。三样凑齐就是一个遥控器。

和 [08](08-claude-code.md) 的 `ccp` 代答是同一个思路换了通道：`ccp` 走 **nvim RPC `chansend`**
把按键送进 nvim 的 terminal buffer；在 tmux 里跑的 claude，用 `tmux send-keys` 就够了，
不用找 socket。08 第 4 节那张**选择题按键序列表和「逐键发、间隔 ~0.2s」的结论照样适用**。

### 实测过的配方（2026-10-11 · tmux 3.8 · Claude Code 2.1.296 · haiku）

```bash
# 1. 起一个后台会话跑 claude（-x/-y 给个尺寸，否则后台会话是 80×24）
tmux new -d -s cc -x 160 -y 50 -c ~/some/project claude

# 2. 发一句话，停一下，再单独发回车
tmux send -t cc -l '帮我看看 README 有没有错别字'
sleep 1; tmux send -t cc Enter

# 3. 读屏幕（-S - 从历史最开头抓，-J 把折行拼回去）
tmux capture-pane -p -J -S - -t cc | tail -40
```

**多行消息**：走 buffer + 括号粘贴，Claude 的输入框会把它当成一次粘贴，换行不会触发提交：

```bash
printf '第一行\n第二行\n第三行' | tmux load-buffer -b msg -
tmux paste-buffer -p -d -b msg -t cc      # -p 括号粘贴，-d 用完删掉这个 buffer
tmux send -t cc Enter                     # 单独再发一个回车提交
```

> 实测 `send-keys -l $'a\nb'`（字面量带换行）也**没有**提前提交 —— Claude 把快速连续的输入
> 当成了粘贴。但这是靠时序碰巧对的，多行一律走 `paste-buffer -p` 才稳。
>
> ⚠ **文字和回车要分开发**（2026-10-11 更正）。第一次实测 `tmux send -t cc '文字' Enter`
> 一条命令能提交，同一天再测就不行了：回车紧跟在文字后面，被 Claude 当成粘贴的一部分，
> 变成了**换行**，消息停在输入框里。`-l` 发文字、`sleep 1`、再单独发 `Enter` 才稳。
> 刚关掉信任框或者刚弹过提示框时更容易出这个问题。

**等它答完**：别去屏幕上找「忙碌」的字样（见下面的坑），用 Claude Code 自己的 **Stop 钩子**发信号：

```json
{ "hooks": { "Stop": [ { "hooks": [
  { "type": "command", "command": "tmux wait-for -S cc-done" }
] } ] } }
```

把上面存成一个文件，`claude --settings 那个文件` 启动（不用动全局 settings.json），然后：

```bash
tmux send -t cc -l '跑一下测试'; sleep 1; tmux send -t cc Enter
tmux wait-for cc-done          # 阻塞到 Claude 这一轮说完
tmux capture-pane -p -J -S -30 -t cc
```

实测发出到 `wait-for` 返回 7 秒，正好是那一轮的耗时。
多个会话就用不同的信号名（比如 `cc-done-$TMUX_PANE`，钩子进程继承了 claude 的环境，能拿到这个变量）。

**其他按键**：

| 想做什么 | 发什么 | 实测 |
|---|---|---|
| 打断正在进行的回答 | `Escape` | ✓ 刚发出就打断的话，**那条消息会被退回输入框**，没有提交记录 |
| 清空输入框 | `C-u`（会提示 `Ctrl+Y` 找回）或 `C-c` | ✓ |
| 切权限模式 | `BTab`（Shift+Tab） | 底栏写着 `shift+tab to cycle` |

### 几个坑

- **新目录会先弹「是否信任此文件夹」**，光标默认在 `No, exit` 上。要么先手动进一次，
  要么发 `Down` 再 `Enter`。⚠ 这个框**认数字键且按下即提交**（08 里记过），别乱发数字。
  **家目录不会被记住信任**，每次在 `~` 下起都会问。
- **别靠读屏判断忙/闲。** 忙碌时那一行是 `✶ Choreographing…` 这种**随机动词 + 转圈符号**，
  每次都不一样，也没有固定的 `esc to interrupt` 字样（老版本有，现在没了）。
  判断「说完了」用上面的 Stop 钩子；非要读屏，就看输入框那行 `❯ ` 后面是不是空的、上方有没有
  `✻ … for Ns · done` 这种收尾行，但这些都是 UI 细节，**Claude Code 升级就可能变**。
- 后台会话默认 80×24，Claude 的回答会折成很多短行，`capture-pane` 时加 `-J`，起会话时给 `-x -y`。
- 历史行数默认只有 2000，本配置调到了 50000，长回答才抓得全。

### 能拼出来的玩法

- **排队**：写个循环，从一个文件里一行一行取任务，`send` → `wait-for` → `capture-pane` 存档 → 下一条。
- **监工**：另开一个窗格跑 `ccw`（08 的看板），或者用 3.8 的 `set-hook -B` 监视 claude 窗格，
  出现权限提示框时底栏标红。
- **多开对比**：同一个问题 `send` 给三个窗格里不同模型/不同目录的 claude，`setw synchronize-panes on`
  也行，最后 `capture-pane` 并排比。
- **pipe-pane 录像**：`tmux pipe-pane -o -t cc 'cat >> ~/cc.log'`，窗格的全部输出持续写进文件
  （带转义序列，看的时候 `less -R`）。

## 7 · Agent Teams：一个队长 claude + 几个队员 claude，每人一个 tmux 窗格

需求是：只跟一个「大脑」claude 说话，由它分派给开发、review、查文档几个小 claude；
哪个小 claude 不对劲，能直接在 tmux 里点进去看、插话。这正是 Claude Code 内置的
**Agent Teams**（实验功能）加上它的 **tmux 分屏显示**，不用自己拿第 5 节那些命令搭。

### 和第 5 节自己搭的区别

| | 内置 Agent Teams（用这个） | 第 5 节自己用 tmux 命令搭 |
|---|---|---|
| 谁创建、管理队员 | Claude Code 自己 | 自己写的 `send-keys` / `wait-for` |
| 队员之间怎么通信 | 内置信箱 + 共享任务列表 | 没有，只能读屏 |
| 结果怎么回到队长 | 队员做完自动带着结果通知队长 | 读屏，很脆 |
| 权限提示 | 汇总到队长那里批 | 卡在各自窗格里没人批 |

tmux 在这里只当**显示器**：`teammateMode` 设成 `auto` 之后，Claude Code 自己调 tmux 给每个队员切窗格。

### 本机怎么开的（cc 模块）

- `~/.claude/settings.json` 合并了三样（`install.sh cc` 的 `cc_teams` 做，只加键、不碰 token）：
  `env.CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS = "1"`、`teammateMode = "auto"`、团队日志的 4 个钩子。
- 三个角色定义在 `~/.claude/agents/`（包内 `claude/agents/`）：

  | 角色 | 模型 | 工具 | 干什么 |
  |---|---|---|---|
  | `developer` | 跟队长 | 全部 | 写代码、跑测试 |
  | `reviewer` | sonnet | 只读 + Bash（看 diff、跑测试）+ 消息/任务 | 审查，只审不改 |
  | `docs-reader` | sonnet | 只读 + WebFetch/WebSearch + 消息/任务 | 查项目文档和官方文档，给出处 |
  | `tester` | sonnet | 读写 + Bash + 消息/任务 | 写并运行测试；**只改测试文件**，bug 报给 developer 修 |

  「任务」指 `TaskCreate/TaskGet/TaskList/TaskUpdate`，写在白名单里是为了**万一开启**任务工具时
  这几个角色能用上 —— 本机默认是**没有**的，见下面「实测踩到的」。

用的时候：**先开 tmux，在 tmux 里启动 `claude`**，然后跟它说：

> 建一个 agent team：developer 类型的队员叫 dev，reviewer 类型的叫 rev，docs-reader 类型的叫 doc。
> 任务是……dev 写完让 rev 审，有疑问问 doc。

队员默认跟角色定义里的模型（developer 跟队长），在这句话里点名模型会覆盖定义里的。
⚠ **本机 `sonnet` 是 Opus 4.8**：`settings.json` 里 `ANTHROPIC_DEFAULT_SONNET_MODEL = claude-opus-4-8[1m]`
（有意设的），所以 reviewer / docs-reader / tester 定义里的 `model: sonnet` 和「都用 sonnet」实际跑的都是
Opus 4.8，状态栏写的就是它。真要压成本只能点名 `haiku`（没映射，是真的 Haiku 5.5）。

### 用完要关：队员会一直常驻

队员**不会自己退出**，一直待命到被关闭 —— 这是设计，方便随时再派活。2026-10-11 练手项目做完后放了 4 个多小时：

- **不花 token**：13:57 之后队长和三个队员的会话记录一条都没新增（每次模型调用都会写一条），团队日志也停在 13:56。
- 但占着 **约 690 MB 内存**（4 个进程），每个 ~0.4% CPU 在轮询信箱。
- 队长面板里队员后面的计时（「4h 18m」）是**从创建算起的**，在面板里选中队员看到的转圈也只是显示，
  不代表在干活 —— 看队员自己的窗格，输入框空着就是空闲。
- 隔很久再派活有个隐性成本：提示缓存只留 5 分钟，队员第一轮要把整段上下文（dev 那次约 95k token）按原价重读。

关法：对队长说「给所有队员发关闭请求」，或者直接关掉整个窗口（进程一两秒内自己退出）。
⚠ 队长面板里**选中了某个队员时，在队长窗格打的字会发给那个队员**（输入框提示变成 `Message @doc…`）。
先用 `↑` 选回 `main` 再回车。

### 关掉之后能恢复吗：团队不能，人和成果能

| 关掉后 | |
|---|---|
| 团队本身（成员名单、信箱 `~/.claude/teams/<团队>/`） | **没了**，会话结束就删 |
| `/resume` 恢复队长 | 能，队长记得全部经过；但**队员不会跟着回来**，它可能给不存在的队员发消息 —— 让它重新建队员即可 |
| 重新建的队员 | **失忆**：只拿到队长给的任务说明，不记得上次的对话 |
| 每个人的完整会话、团队日志、代码、角色定义 | 都在 |

所以「下次接着干」的正确姿势是**关之前先让队长写交接文件**（比如项目里的 `docs/progress.md`：
需求、做了什么、定过的规则、测试怎么跑、遗留问题、协作教训），提交进仓库。下次 `claude --resume`
恢复队长、或者干脆开个新队长，读这一个文件再建队员，不依赖任何会话记录。
2026-10-11 照这个流程收尾 team-demo：队长写了 110 行的 `docs/progress.md`（需求、做了什么、三条规则、
测试、遗留问题、7 条协作教训）并提交，再给三个队员逐个发关闭请求，进程 18:09 全部退出，
`~/.claude/teams/` 下这个团队的目录也随之清掉。
⚠ 开启团队功能后**每个新起的 claude 会话**都会建一个 `~/.claude/teams/session-xxxxxxxx/`（只有 team-lead
一个成员），看到不认识的别当成残留去删，会话结束时自己会清。
（理论上还能 `claude --resume <队员的会话 id>` 单独「复活」一个带记忆的队员，但它回不到团队里，
上下文还要按原价重读 —— 没试过，也不太值得。）

### 队长必须在 tmux 里启动吗

- **`auto`（本机设置）**：在 tmux 里启动 → 分屏；不在 tmux 里 → 退回「不分屏」模式
  （所有队员在队长终端里，用面板上下键切换着看）。**要分屏就得在 tmux 里启动。**
- **`tmux`（强制）**：不在 tmux 里也会分屏 —— 实测它**另起一个独立的 tmux 服务器**
  （socket 是 `/tmp/tmux-$UID/claude-swarm-<队长 pid>`，会话名 `claude-swarm`），队员都在那里面。
  要看得另开一个终端 `tmux -L claude-swarm-<pid> attach`，队长退出时那个服务器一起关。
  能用，但不如直接在 tmux 里启动顺手。

### 和第 1 节免前缀 Alt 层的关系（2026-10-11 实测：不冲突）

独立 tmux 服务器加载新配置，haiku 队长建一个 docs-reader 队员读 README 回报，全程正常：
25 秒切出队员窗格（队长左 30%、队员右 70%），`Alt+l` / `Alt+h` 在队长和队员之间切换、
`Alt+m` 放大队员窗格都正常，队员做完后窗格自己关掉。不冲突的原因（读 2.1.296 的调用）：

- Claude Code 指挥 tmux 一律用 **`%pane_id` / `@window_id`**，不用编号 —— `base-index 1` 不影响它；
- 它给队员窗格**单独**设 `pane-border-format`（`-p`，用队员的颜色），盖过本配置的全局格式，所以
  队员窗格标题是它自己的样式，别的窗格还是本配置的；`pane-border-status top` 两边设的一样；
- 队员之间的消息走信箱文件，不经过 tmux 按键；队长面板的键（`↑/↓`、回车、`Esc`、`←` 看队员、
  `Ctrl+T`、`Ctrl+O`、`Shift+Tab`）都不是 Alt 键；
- `teammateMode = "tmux"` 在 tmux 外另起的 `claude-swarm-<pid>` 服务器也会读 `~/.tmux.conf`，Alt 层同样可用。

要注意的三点：

- **`Alt+q` 关的是整个标签**：在团队那个标签里按，队长和所有队员一起没（多窗格时会先问一次 y/n）。正常收尾还是对队长说
  「给所有队员发关闭请求」，先写交接文件（见上面「关掉之后能恢复吗」）。
- **别在团队标签里自己分屏**（`Alt+\` / `Alt+-` / `Alt+n`）：它重排布局时按整个窗口的窗格列表来
  （`select-layout main-vertical` / `tiled`），你加的窗格会被一起摆。`team-log.sh -f` 这种放
  **新标签**（`Alt+Shift+N`）里。
- 被 Alt 层盖掉的两个 Claude 键：`Alt+o` fast mode 用 `/fast`，`Alt+j` 终端面板先 `Alt+0` 锁定再按。
  反过来 `Ctrl+B`（命令转后台）因为前缀改成 `C-q` 能用了。

### 怎么看队员在干什么

| 想看什么 | 怎么看 |
|---|---|
| 某个队员的完整过程 | 它的窗格：收到的消息（`ctrl+o` 展开）、调的工具、回答，全在里面 |
| 跟某个队员直接说话 | 点进它的窗格打字，不经过队长（实测有效） |
| 谁在忙、忙了多久 | 队长窗格底部的面板：`● main` / `◯ dev  任务名  1m 3s` |
| 屏幕太挤 | `Alt+m` 放大当前窗格；`前缀 w` 树状列表带预览；窗格标题就是任务名。在 `Ctrl+/` 浮动终端里开的 tmux：`Alt+=` 把浮窗切到大档（默认封顶 110 列），再不够就 `SUPER+D` 最大化 kitty，见 [04](04-neovim.md) |
| **队员之间说了什么** | **团队日志**（下面），队长看不到这部分 |
| 事后复盘某个队员做了什么 | 每个队员的完整会话单独存在 `~/.claude/projects/<项目路径转义>/<会话id>.jsonl`，里面有 `"agentName":"dev"` 能认出是谁；比如查谁改了哪些文件：`jq` 筛 `tool_use` 里 `name` 是 `Write`/`Edit` 的 `input.file_path` |

### 怎么吩咐某一个队员

可以，而且是常态：队长发消息**必须写收件人名字**（`dev` / `tester` / `doc`），只进那个人的信箱，
别人看不到。反过来**没有群发**，通知所有人要逐个发。team-demo 里队长发的 12 条消息全是点名单发的
（团队日志实录）：

```
13:49:15  队长 → dev：要求 argparse 参数错误全中文
13:49:23  队长 → tester：参数错误要断言真正的中文提示
18:08:38  队长 → dev：关闭 dev        ← 关闭也是一人一条
18:08:45  队长 → tester：关闭 tester
```

你这边有三条路：

| 方式 | 怎么做 | 队长知道吗 |
|---|---|---|
| **让队长转达**（平时用这个） | 对队长说「让 dev 把 X 改成 Y，别的队员不用动，你别自己改」 | 知道 |
| 点进队员窗格直接说 | tmux 里点 dev 的窗格打字 | **不知道**，除非队员自己汇报 |
| 队长面板选中队员 | `↑/↓` 选 dev → 回车，输入框变成 `Message @dev…`，打的字直接给 dev | **不知道** |

- 绕过队长直接改了东西，记得顺手告诉队长一声，不然它下一轮还按旧的情况指挥。
- 点名要明确、还要说「你别自己动手」—— 官方文档提醒过队长有时会自己干，不分派。
- 空闲的队员收到消息会被唤醒，不用担心它「睡着」；但空闲超过 5 分钟缓存就过期了，第一轮按原价重读上下文。
- 队员得还活着：团队关了 `dev` 这个名字就不存在了，先让队长重建。
- 「任务列表里按人分配」本机用不了（要任务工具，见「实测踩到的」），只能靠消息点名 —— 实测完全够用。

### 团队日志：队员之间的对话队长看不到

队员 A 直接发给队员 B 的消息**只出现在 A、B 两个人的窗格里**，队长只收到发给它的消息和
队员做完时的汇报；信箱文件（`~/.claude/teams/<团队>/inboxes/`）会话结束就删。所以挂了钩子，
每条消息、每次空闲、每个任务建立/完成都记一行到 `~/.claude/team-logs/<日期>.jsonl`：

```bash
~/.claude/team-log.sh        # 今天的日志，人读格式
~/.claude/team-log.sh -f     # 跟随 —— 开个 tmux 窗格放着，就是一个「团队频道」
~/.claude/team-log.sh -r     # 原始 JSON
```

实测长这样（两个 haiku 队员，doc 读 README 给 rev，rev 审 calc.py）：

```
13:20:53  ✉ doc → rev  这个项目是一个极简演示程序：输入两个数字，输出它们的和（README.md:2…
13:21:15  ✉ rev → doc  审查结论：有阻塞问题。calc.py:2 的 add 写成了 a - b，和需求相反 ⏎ - 阻塞 …
13:21:37  ✉ rev → team-lead  审查结论：有阻塞问题。calc.py:2 的 add 实现为 a - b …
13:21:43  ⏸ rev 空闲
```

钩子字段文档没写全，实测（2.1.296）：队员发的 `SendMessage` 带 `agent_type`（角色名）但**没有队员名**，
发送方要从 `tool_response.routing.sender` 取；队长发的没有 `agent_type`；`TeammateIdle` 带
`teammate_name` / `team_name`。所以脚本把 stdin **原样**存下、只加时间戳，显示时再挑字段。
⚠ 钩子调用带 `--hook` 参数，不靠「stdin 是不是终端」判断 —— 从脚本里手动查看时 stdin 也不是终端，
第一版就这么误判过（手动查看被当成了钩子调用，什么都不显示）。
⚠ 钩子脚本**永远 exit 0**：`TeammateIdle` / `TaskCompleted` 的 exit 2 意思是「不许停 / 不许完成」，
日志写失败绝不能变成卡住队员。

### 实测踩到的

- **队长的地址是 `team-lead`**，不是 `lead`。队员按自己的理解发给 `lead` 会被退回
  （`Not sent — no agent named 'lead' is reachable`），它会自己改，但白跑一轮。已写进三个角色定义。
- **队员之间会互相客套**（「收到」「好的，我等 rev 的结论」），每条消息都让对方再跑一轮、花一份钱。
  角色定义里加了「不发纯确认消息」。
- **队员在自己的会话里写 `main` 指的是它自己**，抄送给 `main` 会被拒，所以队长只能写 `team-lead`。
- ⚠ 官方文档说：开启团队功能后，Claude 平时委派工作时**给 subagent 起了名字，那个 subagent 也会变成队员**，
  也就是没要团队也可能冒出团队。嫌这样就把 settings.json 里的开关改成 `"0"`（改完立即生效，不用重启）。没实测。
- **共享任务列表建不起来：本机队长和队员都没有任务工具**（`TaskCreate` 等）。原因是**模型**，不是分屏：
  任务工具只在老模型（Opus 4–4.7、Sonnet 4–4.6、Haiku 4.5、Claude 3.x）上默认提供，**Opus 5.5 /
  Sonnet 5.5 默认不给**，经网关的自定义模型名也不给（官方 tools-reference「Task tool availability」，
  v2.1.268 起）。分屏队员是独立进程，看它自己的模型。于是进度只能靠消息口头汇报，`~/.claude/tasks/<团队>/` 是空的。
  想要就 `CLAUDE_CODE_ENABLE_TODO_TOOLS=1 claude` 启动（或写进 settings.json 的 `env`，但那样**所有**会话
  都多带这几个工具的定义、占上下文，所以没默认开）。⚠ 开了之后分屏队员能不能继承这个变量**没实测**。
  ⚠ 2026-10-11 先误判成「分屏模式拿不到」，后来查文档才更正 —— 第一次正式用（下面）队员自己报出来的。
  任务工具是什么、开了有什么用、要不要开，见下面「任务工具是什么」。
- 中途可能弹提示框（这次是 auto mode 计费说明）卡住队长，要按回车。有人看着的时候无所谓，无人值守时注意。
- 关掉 tmux 会话后，队长和队员进程过一两秒自己退出，没有留下孤儿进程。
  ⚠ 查残留进程别用 `pgrep -f` 加 `kill` —— 模式会匹配到执行它的那个 shell 自己（退出码 144，
  和 `CLAUDE.md` 坑 14 一模一样，这次又踩了一次）。用 `pgrep -x 2.1.296` / `pgrep -x claude`
  再读 `/proc/<pid>/cmdline` 确认。

### 第一次正式使用（2026-10-11，`~/team-demo`）

练手项目：命令行待办工具 `todo.py`（需求在 README），队长 Opus 5.5，dev / tester / doc 三个队员点名用 sonnet（本机实际是 Opus 4.8，见上），
约 15 分钟做完：`todo.py` 249 行、25 个 unittest 全过。过程里看到的、值得记下的：

- **分工守住了**：从各自的会话记录查，tester 只写过 `tests/` 下的文件，dev 只写过 `todo.py`。
  角色定义里「只改测试文件」这种靠说明约束的规矩，这次是被遵守的（不是工具层面强制的）。
- **队长自己抓出了测试的漏洞**：dev 最初的参数报错是「错误：」接 argparse 英文原句，
  tester 第一版只检查「输出里有中文」，照样通过。队长发现后让 dev 全改中文、让 tester 加
  「不能有英文原句」的断言。队长汇报前还自己重跑测试，发现 tester 声称加了的一个用例其实没加。
  → **队长不能只转述队员的话，要自己验证** —— 这次它做到了，以后给队长的指令里也值得写明。
- **tester 一个 bug 都没报过**，「测试—修复」循环其实没真正转起来；唯一的缺陷是队长发现的。
  练手项目太简单可能是原因之一。
- **队员会报「已发送」但其实还没发**：doc 告诉队长「笔记已发给 dev 和 tester」，团队日志显示
  它 50 秒后才真正发给 dev，dev 先抱怨了一轮没收到。**这种事只有团队日志看得出来**。
- **消息交叉**：队长重复提了一个 dev 已经做完的要求（它跑的是旧版文件），dev 识别出是交叉、没返工，
  只是多了一轮对话。
- 中途队员向队长发了好几条「待命 / 本轮结束」之类的状态消息，角色定义里「不发纯确认」的规矩没完全挡住。

### 任务工具是什么、要不要开

**不是 GitHub 上的独立项目**，是 Claude Code 自带的四个内置工具，相当于一份结构化的待办清单：

| 工具 | 作用 |
|---|---|
| `TaskCreate` | 建一个任务 |
| `TaskList` | 列出所有任务和状态 |
| `TaskGet` | 看某个任务的详情 |
| `TaskUpdate` | 改状态、认领、设依赖、删除 |

前身是 `TodoWrite`（Claude 干活时列的那种 checklist）。Claude Code 本身不开源，GitHub 上的
`anthropics/claude-code` 主要收 issue 和发更新日志。⚠ 别和老名字 `Task` 混：那是「派 subagent」的工具，
2.1.63 改名成了 `Agent`，跟这里无关。

**单个会话里**：把多步骤的活拆成清单，做完一项勾一项。
**团队里**它就是「共享任务列表」，用处大得多：

- **状态**：待办 / 进行中 / 已完成，大家看同一份，存在 `~/.claude/tasks/<团队名>/`；
- **依赖**：比如「tester 写测试」依赖「dev 实现 todo.py」，dev 没做完前这个任务谁都领不走；
- **认领**：队员做完手上的会自己去领下一个没人做、没被卡住的任务，同时领有文件锁，不会撞车；
- **看板**：队长界面 `Ctrl+T` 看全局进度；
- **质量关卡**：挂 `TaskCompleted` 钩子，比如「测试没全过不许标完成」。本包的团队日志钩子也监听任务创建/完成，
  只是本机没有任务工具，一条都没触发过。

为什么本机没有、怎么开，见上面「实测踩到的」。要不要开：

| 开的好处 | 开的代价 |
|---|---|
| 队长建好带依赖的任务，队员自己去领，不用一条条发消息派活 | 每个会话都多带这几个工具的说明、占上下文；写进全局设置，平时不用团队的会话也白付 |
| `Ctrl+T` 一眼看全局，不用读消息拼凑进度 | 官方说任务状态有时更新不及时，队员忘了标完成会卡住后面依赖它的任务 |
| 能挂「不许标完成」的质量关卡 | team-demo 证明只靠消息点名也完全跑得通 |

结论：3 个队员一条线做下去的活（team-demo 这种），消息够用，不值得开。任务多了（十几个、互相有依赖、
希望队员自己领活）再考虑，而且**只在那次启动时**用环境变量开，别写进全局设置。

### 不分屏模式：能不能等某个队员做完，再接着跟它聊

> 下面来自官方文档，本机**还没实测过**不分屏模式（只测了 tmux 分屏）。

能，而且在「接着聊」这件事上**不分屏比 tmux 分屏更强**。入口是队长输入框下方的代理面板：

1. `↑/↓` 选中队员 → 回车，进入它的会话视图，能看到它的完整过程；
2. 输入框变成 `Message @dev…`，打的字直接发给它，它**带着之前的全部记忆**接着干；
3. `Esc` 取消选中、回到队长 —— ⚠ 它正在干活时这个 `Esc` 会**打断**它。

不用盯着等它做完：队员做完会自动通知队长并附上最终结果（队长界面出现 `Teammate @dev finished`），看到再进去接着聊。

**比分屏强的地方：停掉的队员能带着记忆「复活」**。队长给一个已经停止的不分屏队员发消息时，
Claude Code 会在同一个会话里把它拉起来、恢复它保存的对话，把这条消息当作下一个输入。
分屏队员是独立进程，关了就是关了，重建的是失忆的。

容易让人以为「它不见了」的情况：

- 所有代理都空闲 30 秒后，空闲的行会**自动隐藏**，但队员还活着、还能被找到 —— 对队长说「给 dev 发消息……」就重新出现；
- 超过 3 个队员空闲时会**折叠**成一行 `2 idle agents`，选中回车展开；
- 看队员时敲的内置命令作用于**队长**：`/compact`、`/clear`、`/rewind` 会先弹确认；`/model`、`/fast` 直接拒绝（队员的模型创建时就定死了）。

边界是**同一个会话之内**：

| 情况 | 能不能接着聊 |
|---|---|
| 同一个队长会话里，队员做完、空闲了 | ✓ 选中它直接聊 |
| 同一个会话里，队员被停掉了 | ✓ 发消息会带着记忆复活（文档说的） |
| 队长退出后再 `/resume` | ✗ 不分屏的队员**不会**跟着恢复，只能重建（失忆） |

顺带：**不开团队功能也行**。普通 subagent 只要有名字，也能用 `SendMessage` 按名字接着聊、带着它之前的上下文。
团队功能多出来的是信箱和队员之间互相通信。

想实测：`claude --teammate-mode in-process` 起个 haiku 队长，建一个队员等它做完 → 面板里选中问它刚才做了什么
（看记不记得）→ 让队长停掉它 → 再给它发消息（看能不能带记忆复活）。

### 两种显示方式怎么选

`auto` 已经替你选好了，这里记一下差别，免得以后疑惑：

| | 不分屏（in-process） | tmux 分屏 |
|---|---|---|
| 看队员 | 面板里上下键选、回车看，一次一个 | 同时看所有人，点进去直接打字 |
| 环境 | 任何终端 | 要 tmux |
| 角色定义的正文 | **追加**在默认系统提示后面 | **替换**默认系统提示 —— 所以本包的三份写得比较完整 |
| `disallowedTools` | 生效 | **不生效** —— 所以本包限制权限一律用 `tools` 白名单 |
| 队员进程 | 在队长进程里，队长退出全没 | 各自独立进程 |

## 8 · 什么时候并行、什么时候一条线做下去

> 2026-10-11 做完 team-demo 之后的讨论。核心一句话：**并行的价值来自「互相独立」，不是「角色多」。**
>
> team-demo 其实是反例：开发 → 测试 → 修复本质是一条线，doc 的调研还把 dev 卡了一轮。
> 一个会话从头做到尾大概也是十几分钟，钱少花一大半。它的价值在于摸清了工具，不在于提速。

### 能不能并行：问四个问题

1. **要不要等别人的结果？** 要 → 串行。
2. **会不会和别人改同一个文件？** 会 → 串行，或者用 git worktree 隔开。
3. **能不能两三句话说清输入、输出、怎样算做完？** 说不清就别派出去 —— 它会不停回来问，或者自己猜。
4. **做完你能不能独立检验它？** 不能 → 它的产出只会堆在你面前等你审。

四个都过，才值得并行。

### 常见几类活

| 活 | 并行 / 串行 | 为什么 |
|---|---|---|
| **开发别的项目** | **并行，最值得** | 完全独立：不同仓库、不同文件、不用互相等。**另开一个 tmux 窗口跑另一个 claude** 就行，不需要团队功能 |
| 搜集资料 | 看情况 | 「同时调研 A、B、C 三个方案再比」适合并行；「先查清楚才能动手」是串行的前置步骤，派个 subagent 查完回来更合适，比常驻一个队员便宜 |
| 开发 + 测试 | **一般是串行的循环** | 测试要等代码，修复要等测试结果。例外：需求写得非常清楚时，tester **照着需求先写测试**、dev 同时写实现，最后合起来跑 —— 这才是真并行 |
| 代码审查 | 可以并行 | 同一份改动，安全 / 性能 / 测试覆盖几个角度同时审，互不影响 |
| 调 bug | 平时串行 | 每一步都依赖上一步的发现。例外：完全没头绪时，几个队员各验证一种猜测、互相反驳（官方推荐的团队用法） |
| 长时间等待（编译、大测试、下载） | 放后台 | 不需要另一个智能体，后台跑着，你接着做别的 |

### 三种工具，按「需不需要交流」选

| 需要什么 | 用什么 | 典型场景 |
|---|---|---|
| 派人查点东西，**只要结果** | 单会话 + subagent | 「查一下这个库怎么用」「搜一下哪里调用了这个函数」 |
| 几件**互不相干**的事同时推进，**你来协调** | **多个 tmux 窗口，各跑一个 claude** | 项目 A 开发、项目 B 修 bug、项目 C 写文档 |
| 几个人**要互相讨论** | Agent Team（第 7 节） | 开发和审查来回改、几种猜测互相反驳 |

开发不同的项目，**多开 tmux 窗口是最优雅的**：简单、零协调成本、每个 claude 只装自己项目的上下文，
`前缀 w` 在它们之间切。团队功能只在「同一件事里几个角色要来回对话」时才划算。
同一个仓库想并行两件事（比如前端、后端），用 **git worktree** 给每个 claude 一份独立的工作目录，避免互相覆盖。

### 最容易忽略的瓶颈：你自己

并行能加快「生产」，但每份产出最后都要你看、你判断、你合并。team-demo 里最值钱的一步是队长发现
「测试全过但没测到点子上」—— 这种检验没法并行，卡在你或队长身上。
**同时开的路数，别超过你审得过来的数量**，否则产出越多积压越多。

### 往下学的顺序

1. **写清楚任务说明**（输入 / 输出 / 完成标准）—— 能不能派出去的前提，比任何工具都重要；
2. **git worktree** —— 同一个仓库安全并行的基础；
3. **检验的习惯** —— 派出去的活怎么快速确认真做对了：测试、实际跑一遍、看 diff；
4. **成本感** —— 每多一个智能体多一份上下文的钱，空闲久了再唤醒要按原价重读；
5. 最后才是工具本身（tmux 多窗口、subagent、团队），这几样已经摸过了。

经验法则：**一个子任务，能两句话说清它要什么、怎样算完成，而且不用等任何人 → 派出去并行；
否则就留在一条线上，一步一步接着做。**

### 让 Claude 自己按这套来（2026-10-14）

上面这些原来只是给人看的，Claude 每次会话不知道。现在写成了两处，让它**默认就照官方的四种用法选**：

- **`~/.claude/CLAUDE.md`「多智能体并行」一节**：单会话（默认）→ 子代理（只要结论）→ Agent Teams
  （队员要互相交流时才用，3–5 人，**只在 tmux 里建队**）→ 多会话 + worktree（用户自己开窗口）。
  放全局 CLAUDE.md 而不是记忆：auto memory 按启动目录分开存，从 `~/cachyOS-config` 起的会话读不到 `~` 的记忆。
  已进 cc 模块，包内叫 **`claude/global-CLAUDE.md`**（故意不叫 CLAUDE.md：放在 `claude/` 下同名，
  Claude 在仓库里改 cc 工具时会把它当成那个目录的项目指令加载）。笔记本若有自己的版本，装 cc 前先 `./sync.sh --diff`。
  ⚠ CLAUDE.md 只是「建议」，Claude 不是每次都照做；这种需要判断的偏好用不上钩子。
- **三个角色的 `description` 加了「主动使用（use proactively）」**：reviewer（改完代码后）、docs-reader（要翻多篇文档时）、
  tester（跑测试看大段输出时）。这是官方让主会话自动派活的写法。**developer 故意没加**：写代码默认留在主会话，
  派出去会丢上下文，只在建队时点名用它。

当初的第一版是「在 tmux 里就优先建队」，比官方激进：能拆的活都会起一个团队，token 花得比单会话多得多，
而官方明说有先后依赖、改同一个文件的活不适合建队。改成现在这样的代价是：在 tmux 里派出去的普通子代理
**不会出现在分屏里**，只有真建队的时候才能看到每个人在干什么。

## 9 · 窗格总览 `Alt+a`：一堆 Claude 和 npm 散在几个会话里，怎么一眼找到（2026-10-13）

### 为什么 `Alt+o` 不够

`Alt+o`（`choose-tree -Zs`）按**会话 → 标签**列，而标签名是 `automatic-rename` 按进程名起的 ——
开了七八个 Claude 时满屏都叫 `claude`，只能一个个展开看。它的 `/` 搜索也只搜名字和屏幕文字，
**不搜窗格标题**。真正能区分它们的信息其实一直都有：Claude Code 会把对话主题写进窗格标题
（窗格顶上那个胶囊显示的就是它），只是 `Alt+o` 不显示。所以换个思路：**按窗格列，按主题 / 命令 / 目录搜**。

### 用法

`Alt+a` 弹出一张表（`display-popup` 里跑 fzf），**所有会话的所有窗格**一行一个：

```
 等你授权  claude  重构登录流程                 …/tradition-medi   tradition-medi:1.1    40秒
 答完了    claude  mmd-view 竖向布局模式        ~                  Projects:1.1          19分
 失败 1    zsh     cargo build --release        …/gaoTest          Projects:1.2           2分
 干活中    claude  tmux 多会话 Claude Code 窗口… ~                  Projects:2.1          15分
 干活中    队员    developer                    …/tradition-medi   tradition-medi:1.2
 运行中    npm     npm run dev                  …/tradition-medi   tradition-medi:2.1   9时12
 空闲      claude  tradition-medi-jingluo-bf    …/jingluo          tradition-medi-jingluo:1.1
 空闲      zsh     —                            ~                  Projects:2.2
```

- **排序就是优先级**：等你的 → 答完/跑完你还没看的 → 干活中 → 运行中 → 空闲，同一档里新的在前。
  所以大多数时候**按 `Alt+a` 直接回车**就是去「最该去的那个」。
- **打字过滤**：主题、命令、目录、会话名都能搜（`jingluo`、`npm`、`mmd`）；`claude` 只筛 Claude。
- 下半屏**预览**那个窗格当前的画面（带颜色），不用跳过去就知道它停在哪；`Ctrl-/` 收起。
- `Enter` 跳过去（切会话 + 切标签 + 选窗格一步到位），`Ctrl-R` 刷新，`Esc` 关。
  `●` 标的是你按 `Alt+a` 时所在的窗格。

| 状态 | 含义 | 从哪来 |
|---|---|---|
| 等你授权 / 等你回答 / 等你处理 | Claude 卡在授权、提问、对话框上 | 会话文件 `status = waiting`，细分原因来自 `claude agents --json` 的 `waitingFor` |
| 答完了 | Claude 停下了，**而且停下之后你没看过它** | `status = idle` 且 `statusUpdatedAt` 晚于 `@seen` |
| 干活中 | Claude 正在跑 | `status = busy`（队员：屏幕上有转圈那行） |
| 失败 N / 跑完了 | 一条跑了 ≥10 秒的命令结束了、你还没看；N 是退出码 | `.zshrc` 写的 `@sh_exit` / `@sh_end` 对比 `@seen` |
| 运行中 | shell 里有前台命令在跑（npm、ssh、nvim…），后面是已跑时长 | `pane_current_command` 不是 shell；命令原文取 `@sh_cmd`，没有就读 `/proc` 前台进程组 |
| 空闲 | 都不是；shell 那行会带上一条命令（失败的前面打个叉） | |

**底栏**（右侧会话圆点前面）同步显示计数：黄铃 = Claude 在等你、绿勾 = Claude 答完没看、
青三角 = 命令跑完没看、红叉 = 命令失败没看，后面跟一个灰色 `Alt+a` 提示；**全是 0 就整段不显示**。
它是 `status-right` 里的 `#(tmux-panes --status)`，跟 `status-interval 5` 走，最多晚 5 秒；一次约 25 ms。
**正在你眼前的那个窗格不计数**（你已经在看了）。

### 状态从哪来：没用 Claude Code 钩子

原本打算用钩子（`UserPromptSubmit` → 干活中、`Notification` → 等你、`Stop` → 答完了）给窗格打标记。
动手前发现 Claude Code 自己就在维护一份状态：**`~/.claude/sessions/<pid>.json`**，
里面有 `status`（`busy` / `idle` / `waiting`）和 `statusUpdatedAt` —— cc 模块的 `ccw` 看板读的也是它（[08](08-claude-code.md)）。
它比钩子准：**按 Esc 打断时 `Stop` 钩子不触发**，钩子方案会一直卡在「干活中」，会话文件则会正确落回 `idle`。
所以 `~/.claude/settings.json` **一个字没改**。

- **会话文件 → 窗格**：顺着 claude 进程的父进程链往上找，碰到哪个窗格的 `pane_pid` 就是哪个。
  ⚠ 会话文件里其实也记了 `"tmux": "Projects:@7.%34"`，但**不带是哪个 tmux 服务器**，
  用 `tmux -L 测试名` 起的测试服务器同样有 `%0 %1`，按它对会认错（实测踩到：测试服务器里冒出了真服务器的「队长1」），所以只认进程树。
- **Agent Teams 的队员没有会话文件**（进程名是版本号 `2.1.273` 这种），退而看屏幕：
  最后 40 行里有「`✢ Hashing… (2m 23s · ↓ 6.8k tokens`」这种转圈行就算干活中。
  ⚠ 这是按 Claude Code 2.1.273 的界面写的正则（`SPIN_LINE`），升级后界面变了要跟着改。
  另外**窗格标题前面的 `✳` 判断不了忙闲** —— 实测在干活的会话标题前面照样是 `✳`。
- **队长常年显示「干活中」不是 bug**：队员在跑时队长的 `status` 就是 `busy`，屏幕上看着却像空闲。

### 「看过没」：`@seen`

`~/.tmux.conf` 挂了 `pane-focus-in` / `pane-focus-out` 两个钩子，窗格得到或失去焦点
（切窗格、切标签、切会话、终端本身切走再切回来）时把当前时间写进窗格选项 `@seen`。
结束时间晚于 `@seen`、而且它现在**不在你眼前**，才算「答完了 / 跑完了」。
「在你眼前」= 当前窗格 + 当前标签 + 所在会话挂着一个**聚焦**的客户端（`client_flags` 里有 `focused`）。
你盯着它答完、再切走时，`focus-out` 会把 `@seen` 刷新到切走那一刻，所以不会被误报成没看过。
配置加载时 `tmux-panes --init-seen` 给还没有 `@seen` 的窗格补上「现在」，不然第一次打开时所有旧窗格都会被当成没看过。

### shell 那一半：`.zshrc` 的 preexec / precmd

只在 `$TMUX_PANE` 存在（在 tmux 里）时启用，见 `.zshrc` 的「tmux 窗格状态」段：

- `preexec`：`@sh_cmd`（命令原文，换行换成 `⏎`，截 300 字）、`@sh_start`
- `precmd`：`@sh_last`、`@sh_exit`、`@sh_dur`、`@sh_end`，并清掉 `@sh_cmd` / `@sh_start`

每个提示符多一次 tmux 调用（约 2 ms，合成一条 `\;` 链）。
**`$?` 在多个 precmd 函数之间是保留的**（2026-10-13 在 pty 里实测：前一个函数 `return 0`，后一个照样看到 1），
所以不用费劲把自己排到 p10k 前面。
⚠ **改完 `.zshrc` 之前就开着的 shell 没有这些钩子**，要 `exec zsh` 或开新窗格才开始记；
在那之前「运行中」的命令原文由 `/proc/<shell>/stat` 的 tpgid 找前台进程组兜底（npm 那两行就是这么来的），
只是没有退出码和耗时。

「跑完了 / 失败」只提醒跑了 **≥10 秒**的命令（`tmux-panes` 里的 `LONG_CMD`）—— `ls`、`git status`
跑完不需要谁提醒你。

### 实测和坑（2026-10-13）

用第 1 节坑 5 的办法起独立服务器测完整链路：在别的会话跑 `sleep 12; false` →
2 秒时显示「运行中 sleep 12; false」→ 结束后「失败 1」、底栏出现红叉 1 → `Alt+a` 弹窗里输入 `other` 回车 →
客户端落在 `other:1.1` → 再看列表变回「空闲」带叉、底栏计数消失。

- **`display-popup` 的命令会展开格式**：`"tmux-panes --from '#{pane_id}'"` 拿到的是按键时所在窗格。
- **`switch-client -t %窗格id` 会连带切标签、选中那个窗格**，不用再拼 `select-window` / `select-pane`。
- **测试时 `send-keys -K M-a` 会阻塞到弹窗关闭**（和第 1 节坑 5 里的 `command-prompt` 一样），
  要放后台：`(tmux send-keys -K -c 客户端 M-a &)`，第一次没放直接卡死了测试脚本。
- 图标全是 Nerd Font 私用区字符，`tmux-panes` 里一律写 `"\uf0f3"` 这种转义（理由同「底栏」那段的坑）。

### 想调的话

- 提醒阈值：`tmux-panes` 顶部 `LONG_CMD = 10`。
- 不想要底栏计数：删掉 `status-right` 开头那段 `#(~/.local/bin/tmux-panes --status)`，`Alt+a` 不受影响。
- 只想看 Claude：在列表里输入 `claude`（队员那几行要输 `队员`）。
